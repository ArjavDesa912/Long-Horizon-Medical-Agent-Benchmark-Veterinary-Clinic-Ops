## Layout

```
environments/veterinary_clinic_system/
  pyproject.toml                                    # verifiers-spec package manifest
  README.md                                          # (auto-generated by `prime env init`, left as-is)
  veterinary_clinic_system/__init__.py               # exports load_environment
  veterinary_clinic_system/veterinary_clinic_system.py  # the adapter
```

The adapter only wires up the **10 open tasks** (the ones with a `verifier.py` on disk in this public sample) — `_load_open_task_ids()` filters to those. Pointing it at any of the 90 gated task ids raises a clear `ValueError`, it doesn't silently no-op.

## Container lifecycle: ported, not reinvented

`_Container` in the adapter module is a line-for-line port of `../../../env.py`'s `VibeDBEnv` container lifecycle (build/run, `/rl/healthcheck.sh` polling, manifest read, login, per-episode nonce injection, teardown) — same image, same ports, same nonce anti-memorization scheme. The reward function (`grade`) shells out to the task's own `verifier.py` exactly the way `env.py`'s `_compute_reward` does, so grading can't drift between the Gymnasium wrapper and this adapter.

## What's left for a human with Prime Intellect access

1. `prime login` (needs the account owner's credentials).
2. From `environments/veterinary_clinic_system/`: `prime env push veterinary_clinic_system` (or whatever the org wants the hub-listed name to be) — **not run here**, needs the account.
3. Decide whether `VETCLINIC_REPO_ROOT` should point at a path baked into the pushed wheel, or be set as an environment secret at eval time — right now it defaults to a relative walk-up from the installed package, which only works when this adapter sits inside the sample repo checkout. If the wheel is installed standalone (no sibling `tasks/`), set `VETCLINIC_REPO_ROOT` to wherever the task files (and the `rl-env/veterinary_clinic_system:latest` image) live.
4. Requires Docker available on whatever machine actually runs the eval/rollout (this is a local-container environment, not a `SandboxEnv`-hosted one — `verifiers` also ships `vf.SandboxEnv` for Prime Intellect's own hosted sandbox infra, which wasn't used here since the existing container image + healthcheck script is the source of truth for this env's lifecycle; worth a follow-up if Prime Intellect requires hosted-sandbox-only environments).
